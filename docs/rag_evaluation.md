# Phase 3 retrieval evaluation

The corpus is fictional demonstration data: six developments, six brochures, two policies, one FAQ, and a canonical JSON inventory. SQLite stores six properties. Chroma's `vocalead_local_multilingual` collection stores 14 genuine vectors from `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; cosine distance is used. Gemini `gemini-embedding-001` is implemented but untested because no Google key is configured.

Run `backend/.venv/Scripts/python.exe scripts/evaluate_rag.py` after setting `EMBEDDING_PROVIDER=local` and `RAG_COLLECTION_NAME=vocalead_local_multilingual` in root `.env`. The 15 labelled cases are in `backend/tests/fixtures/rag_evaluation.json`. Hit Rate@K is the fraction of evidence cases with an expected source/property in retrieved chunks. Recall@K is the fraction of expected property IDs retrieved. MRR is mean reciprocal rank of the first expected property. Strict violations count units exceeding a requested budget. No-evidence detection counts cases with no returned chunks. These metrics measure retrieval, not generated answer correctness.

Actual run: Hit Rate 0.3846; Recall@K 0.30; MRR 0.2308; strict budget violations 0; no-evidence detection 2/2; mean retrieval latency 1563.5 ms. This is a low-performing baseline. The Hindi and Hinglish cases returned no source at the provisional 0.6 cosine-distance threshold; multilingual retrieval is not yet reliable.
